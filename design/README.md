# Design decisions

Save small explanations of decisions you can defend. Start after practising the related code or backend concept.

Examples: when a Set is useful, why transfer balances need an atomic transaction, what happens if an API request is retried, or what an index costs on writes.

One note should contain: a concrete requirement, two possible approaches, your choice, its trade-off, and a failure scenario. Draw a small diagram only if it helps explain the flow. Revisit the note when actual code contradicts your assumptions.

Begin with one LedgerFlow decision you have inspected. Advanced distributed-system designs can wait until the baseline shows a need.
